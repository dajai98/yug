# Phase 3 evidence bundle v1 (zero authority)

`training/evidence_bundle.py` packages exact evidence references and verifies them offline. It does **not** grant rights, intended use, production admission, export, accounting, or training. Existing governance and corpus gates remain authoritative. No prospective source decision is made by creating a bundle.

## Format and identity

`manifest.json` is canonical UTF-8 JSON: sorted keys, ASCII escaping, no whitespace, no NaN, and no duplicate keys. Its `identity` is `sha256:` plus SHA256 of the same canonical object without `identity`, using YUG's existing `training.production_corpus.identity`. A verifier must receive this identity from an independent trusted channel; a self-seal alone does not prevent replacement. Noncanonical serialization is rejected.

The manifest fields are `schema=yug-evidence-bundle-v1`, `mode` (`development` or `production`), `source` (`source_id`, canonical `locator`, exact 40-character Git `revision` or historical `UNKNOWN`), sorted unique `files` (`path`, `sha256`, Git `git_blob` or `UNKNOWN`, and a relative `artifact_path` for exact saved bytes), sorted unique `artifacts` (`role`, relative `path`, exact byte `sha256`, `bytes`), `decision_scope`, and `lineage` (`dataset_versions`, `model_versions`). Every referenced artifact is hashed from its saved bytes; a known Git blob ID is recomputed from saved file bytes. Paths are relative to an explicitly supplied root; traversal, absolute paths, case-insensitive duplicates, missing artifacts, and malformed records fail. Production mode requires source-inventory, license, and intended-use decision artifacts, plus a `source_file` artifact matching each exact file hash. `decision_scope` must exactly repeat the source and file set and point to a bound `intended_use_decision` artifact. The verifier compares the actual sealed one-file v1 or multi-file v2 decision against this scope; unsupported future decision schemas fail closed. This is **packaging consistency**, not independent proof that the decision was valid or authorized. The production gate must still check the actual decision's policy, reviewer, scope, and external authority pins. Future dataset/model lineage is reported only from explicit recorded identities; an empty list or `UNKNOWN` is not a claim of consumption.

`build_manifest(root, specification)` computes a reviewable in-memory manifest; the caller may save its canonical bytes. It does not sign or publish anything. Historical `UNKNOWN`/`MISSING` information remains explicit and cannot be converted to a production decision scope. The current 174 retained items across eight sources can be wrapped by referencing saved license bytes, source clearances, exact file manifests, build/ledger evidence, and historical reviews as immutable artifacts. No historical input is rewritten. An anchor obtained now proves existence by that anchor time at most, not at the original acquisition date.

## Signatures and external trust

Production mode requires a detached Ed25519 signature. Sign the bytes `YUG-EVIDENCE-MANIFEST-V1\0` followed by the ASCII manifest identity. A canonical `yug-evidence-signature-v1` artifact contains `schema`, `algorithm=Ed25519`, `manifest_identity`, `public_key_sha256` (SHA256 of the PEM bytes), and Base64 signature. The compatible v2 signature adds `key_id`, which must equal the externally pinned key identifier. Verification uses OpenSSL `pkeyutl -verify`; no private-key path or signing command exists in production code. Development mode may be unsigned and reports `UNSIGNED_DEVELOPMENT_ONLY`; it cannot become production mode by relabeling because the external manifest pin changes. Missing/invalid signatures, missing OpenSSL, or an untrusted/mismatched key fail closed in production mode. At the time this foundation was implemented, it created no production key; the separate KEY-002 ceremony later activated a public trust pin. Ephemeral private keys used by tests are test-only and remain in temporary test directories.

### Production signing trust policy v1

The offline key ceremony, independent pin retention, backup, lifecycle, rotation, and compromise procedures are specified in [EVIDENCE_SIGNING_CEREMONY_V1.md](EVIDENCE_SIGNING_CEREMONY_V1.md). KEY-002 now has an externally retained `ACTIVE` public trust-pin identity `sha256:5002095d341ee82ef19a4720932bfe5472ba39f3ec296325f7b3336638abec63`. This document and its machine-readable schemas create no trust root or signing key; no production bundle or RFC 3161 response is claimed here.

`training.evidence_trust` validates canonical `yug-evidence-trust-pin-v1` JSON. Required fields are `schema`, `key_id` (`YUG-EVIDENCE-KEY-` followed by at least three digits), `algorithm=Ed25519`, `public_key_sha256`, relative `public_key_path`, `status`, UTC `valid_from`, UTC `valid_until` or `UNKNOWN`, `predecessor_key_id` or `NONE`, `governance_decision_identity`, and canonical `identity`. The identity is SHA256 of the canonical object without its `identity` field. The fingerprint hashes the exact public PEM bytes; changing the PEM encoding changes the pin. The operator supplies an **independently trusted exact trust-pin identity**, the trust-pin file, and its public-key root. Bundle + signature + public key + a locally self-created pin are insufficient. Production verification rejects direct public-key paths as a substitute for this external pin. A trust pin confers no source rights or training authority.

The production private key is separate from Git, bundle storage, public PEM, trust pin, signature artifact, and human/governance authority. A key ceremony must name accountable custodians, record the external governance decision before generation, generate the key in approved protected storage, recompute and verify the exact public-key fingerprint, establish a backup/recovery and access-control plan, and publish the trust-pin identity through channels independent of mutable bundle storage. For the private solo-owned YUG system, the documented `SOLO_CUSTODIAN_TWO_STEP_REVIEW` requires a separately recorded second self-review and a distinct later activation decision; it does not claim an independent human reviewer. No production key generation, import, export, backup, or signing ceremony is performed by this module. Development/test keys must use separate identifiers and must not appear in the production trust registry.

Statuses are `ACTIVE`, `RETIRED`, `REVOKED`, and `COMPROMISED`. An active pin is checked against its UTC validity interval for normal production verification. Rotation creates a new key and independently approved new pin with `predecessor_key_id`; it never rewrites old signatures. Retired keys may be checked only in explicit **archival integrity** mode, which returns `VERIFIED_RETIRED_ARCHIVAL_ONLY` and grants no current authority. Revoked or compromised keys fail even archival verification in the current implementation. A verified timestamp and independently established compromise time could later support a narrower pre-compromise historical claim, but neither is inferred from a local status field. Preserve old public keys, pins, signatures, timestamps, and external pin records; do not silently replace them.

### Multi-file intended-use decision v2

The one-file `yug-source-training-use-decision-v1` remains unchanged. A separate sealed `yug-source-training-use-decision-v2` supports a bounded exact multi-file set. Required fields are `schema`, `decision`, `source_id`, `locator`, exact `revision`, `intended_use`, `split`, `owner`, `subcategory`, sorted `files`, `rights_review_identity`, `attribution`, `notice_obligations`, `obligations`, `max_files`, `max_raw_bytes`, `max_accepted_tokens`, `reviewer`, `decided_at`, `governance_decision_identity`, and `identity`. Each file contains exact `path`, `sha256`, `git_blob` or `UNKNOWN`, positive `bytes`, `source_clearance_identity`, and `file_clearance_identity`. The verifier requires exact equality of the decision's source and ordered path/hash/blob set with the bundle; it rejects omitted, extra, reordered, duplicate, case-colliding, or widened files. Each file's saved bytes and known Git blob are verified independently; total raw bytes must fit the decision cap. Changing split, intended use, attribution, NOTICE obligations, or any clearance identity changes the sealed decision bytes and therefore the signed manifest identity. The only accepted use/split pairs are `commercial_training/train` and `evaluation/validation`. This schema **does not issue a decision**: a human/governance workflow must create and externally approve each decision and all existing admission gates still apply.

## Trusted time

[RFC 3161](https://www.rfc-editor.org/rfc/rfc3161.html) time stamping is mandatory for **production-mode verification**. The production policy is `SIGNATURE_REQUIRED` and `TIMESTAMP_REQUIRED`; there is no caller-controlled downgrade or silent offline exception. A production manifest cannot verify without both a receipt and an independently supplied TSA CA, and OpenSSL must validate the response signature, chain, and imprint. Development mode may omit a timestamp but grants no authority; a production trust pin cannot verify a development manifest. The message imprint is SHA256 of the ASCII manifest identity, so only a digest needs to leave the local system. Store the original request (`.tsq`), response (`.tsr`), nonce, TSA policy OID, TSA certificate chain, CA/trust-anchor identity, verification metadata, and archival revocation/validation material where feasible. Offline verification uses [OpenSSL `ts -verify -digest ... -in ... -CAfile ...`](https://docs.openssl.org/master/man1/openssl-ts/) against the independently supplied TSA CA. Verify request nonce and policy when applicable; archive certificate status/revocation material and renew or re-anchor before algorithms/certificates expire. The verifier does **not** claim nonce/policy or long-term revocation validation when only a `.tsr` is supplied. A caller requiring those properties must preserve and verify the original request and archival validation data before treating the timestamp as a trusted-time anchor. A timestamp obtained now proves existence no earlier than its actual date. This change sends no request and contacts no production TSA.

## Evidence log design (not active)

Use a separate append-only evidence log, not the cumulative corpus ledger. A future `yug-evidence-log-event-v1` should bind `schema`, monotone `ordinal`, `previous_head`, `bundle_identity`, `manifest_identity`, `signature_identity`, `trust_pin_identity`, `timestamp_receipt_identity` or `MISSING`, `event_type`, and `resulting_head=SHA256(canonical event without resulting_head)`. Genesis uses ordinal zero and a fixed documented predecessor; each following event increments by one and names the exact prior head. Reject broken predecessors, reordered ordinals, duplicate bundle identities, or replacement; compare the final head with an independently retained pin to detect truncation or wholesale rewriting. Append atomically under a single-writer lock and externally preserve/pin or periodically timestamp the head. A local hash chain without an external head cannot alone prevent silent historical replacement. This foundation writes no evidence log and does not change the corpus ledger.

## Offline check

```text
python -B -m training.evidence_bundle --root <retained-evidence-root> --manifest <manifest.json> --expected-identity sha256:<externally-trusted-manifest-pin> --signature <signature.json> --trust-pin <trust-pin.json> --expected-trust-pin-identity sha256:<externally-trusted-trust-pin> --trust-root <public-key-root> --timestamp <response.tsr> --tsa-ca-file <trusted-ca.pem>
```

`verify_bundle` returns only artifact/file counts, signature/timestamp/key status, declared lineage, and `authority=NONE`. Verification is offline and does not authorize any source. Do not derive either external identity pin from mutable local files. Do not treat `MISSING` timestamps or historical `UNKNOWN` values as verified evidence. The future master source register may reference the bundle/manifest identities, signature/timestamp status, production decision, and dataset/model versions, but no existing audit evidence or source register is rewritten here.
