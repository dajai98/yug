Evidence ledger for YUG Core v2. Created 2026-10-22. This is not an implementation plan or authorization to copy code, prompts, architectures, models, or dependencies.

Do not read an entry as proof that its system was independently evaluated.

Evidence notation: **V** = directly verified observation; **P** = project/vendor-reported mechanism; **I** = YUG relevance inferred from evidence; **U** = unverified identity, version or claim. Linked primary pages were consulted on 2026-10-22; they are live references unless an explicit version anchor is listed below. Version anchors identify artifacts, not reproduced YUG evaluations. For linked entries, V establishes that the cited page describes the mechanism, not that the mechanism works as claimed. All proposed YUG relevance/component mappings are I. For unlinked entries, the mechanism column records a tentative study question, not an attributed implementation fact.

Status **UNEVALUATED** means no independent YUG outcome exists. **VERIFY ID** means resolve the exact source before attributing mechanisms. No entry has earned a YUG PASS or FAIL. Extend entries with canonical URL, revision/version, claim, evidence location, reproduction and outcome; do not promote confidence from popularity or name similarity.

## Convergent Principles

These are the requested cross-system research synthesis, not a verified consensus or adopted architecture. Primary descriptions above corroborate parts of specification workflows, context organization, review and visual production. Independence, effectiveness and the remaining study attributions still need retained evidence. Repetition across related projects is not independent validation.

- Goal → Specification → Plan → Task DAG → Execute → Verify; maintain persistent structured project context and dependency-aware project/code intelligence.
- Agent != Skill != Tool != Verifier; persistent agents != temporary subagents. Keep lifecycle, capability and verification responsibilities explicit.
- Scoped capabilities and least-capability exposure; external security enforcement rather than prompt-only security; read-only audit separated from modification authority.
- Independent verification with PASS / FAIL / UNEVALUATED. Missing evidence is UNEVALUATED, not PASS.
- Memory consolidation: experience != trusted memory. Use progressive context/skill retrieval instead of giant prompts.
- Capability registry and runtime capability probing; capability/provider/model-version selection based on actual task requirements.
- Execution dispatcher separated from planner; an agent runtime envelope defining authority, resources, state and termination conditions.
- Evidence/provenance-backed investigation; minimal sufficient change; evidence-before-refactor.
- Observability/trajectory tracing; resumable/checkpointed workflows; precondition gates before expensive downstream work.
- Bounded simulation for uncertain/high-consequence decisions; simulation outputs remain hypotheses requiring external checks.
- Render/observe/correct loops for visual and 3D work; an appealing render does not establish topology, rig or engine correctness.

## GameDev / 3D Research

Emerging research pipeline, not an implemented YUG workflow:

```text
Design intent / reference
→ Asset Production Specification
→ capability/model selection
→ generation / structured intermediate representation
→ geometry
→ topology/remesh
→ UV/materials/PBR
→ rig compatibility check
→ rigging
→ animation
→ render and visual inspection
→ optimization
→ Unity/Unreal import
→ engine/performance verification
```

The supplied research history identifies Meshy, Tripo, TRELLIS.2, img2threejs, Three.js Object Sculptor, Anatomy, OpenMontage and Open-Higgsfield-AI as informing different parts of this picture. The linked primary sources support generation/representation and some downstream feature descriptions; exact contributions of the unresolved names remain unverified. This does not establish that any one tool implements the entire pipeline.

Candidate evaluation should bind units/axes/scale, geometry and topology constraints, UV/material requirements, skeleton compatibility, animation requirements, target engine/version and performance budgets to the asset specification. Validate artifacts at each relevant stage, including actual engine import and measured performance. Do not infer rig suitability or game readiness from a marketing claim or preview render. Provider access, output rights, provenance and resource feasibility remain separate preconditions; no provider is selected here.
